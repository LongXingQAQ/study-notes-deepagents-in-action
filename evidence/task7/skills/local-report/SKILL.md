# 本地资料报告

根据用户指定的本地资料编写报告，保留来源，并核验实际保存的内容。

## 确认输入

需要明确：
- 使用哪些资料文件。
- 报告的主题和具体要求。
- 保存报告使用的 slug。

缺少必要信息时，先向用户询问。

## 工作流程

1. 使用 write_todos 规划读取资料、编写报告、保存报告和读回核验。
2. 使用 read_source 读取用户指定的资料，等待实际返回结果。
3. 使用 read_file 读取报告模板：
   `/skills/local-report/assets/report-template.md`。
4. 根据已读取的资料和模板编写报告，满足用户的具体要求。
5. 使用 save_report(slug, content) 保存报告。
6. 保存成功后，使用 read_report(slug) 读回报告。
7. 检查读回内容是否满足要求，来源标注是否保留。
8. 核验通过后，更新 Todo，再向用户说明保存路径和结果。

每个有依赖的步骤，都必须等待前一步工具返回后再继续。

## 资料缺失处理

当 read_source 返回文件不存在时，按以下顺序处理：

1. 只允许额外调用一次 glob，在 /sources/ 内查找原文件名。
   例如，缺失 task7-missing-notes.md 时，参数必须是：
   {"pattern": "**/task7-missing-notes.md", "path": "/sources/"}

2. 不扩大到工作区根目录 /，不进行第二次 glob，
   不改用 ls、grep 或读取其他资料继续寻找替代文件。

3. 如果找到唯一对应文件，使用实际路径重新读取。
   如果结果不唯一，先请用户确认，不自行选择。

4. 如果没有找到，立即说明缺失的文件名，
   请用户补充文件或确认路径，结束本轮处理。
   不自行使用名称相似的资料替代。

5. 必需资料未成功读取前，不生成或保存正式报告，
   不把报告编写、保存和核验任务标记为完成。

如果是权限错误或其他读取错误，说明实际错误，
不进入文件查找流程。

## 内容与完成要求

- 只依据实际读取的资料，不编造事实或来源。
- 自编练习资料应明确注明其性质。
- 不联网、不生成图片、不修改原始资料、不委派子 Agent。
- 如果模板缺失，说明缺失路径并停止编写。
- 如果保存或读回失败，保留对应任务未完成状态。
- 如果读回内容不符合要求，修正后重新保存、读回核验。
- 用户没有允许覆盖时，不覆盖已有报告，应先询问。
